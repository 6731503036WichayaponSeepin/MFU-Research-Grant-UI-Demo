# Implementation and validation report

## Implementation summary

Preserved the existing application and MFU identity. Connected researcher/staff dashboards to shared projects; centralized the official nine statuses and legacy aliases; added safe fictional-data initialization and confirmed reset; implemented shared draft/submission/revision records; added external certification/committee recording and earlier administrative handoffs; replaced notification placeholders with project history and persistent read state. Existing closure, reviewer, and change-record workflows remain in place and use the shared storage reader.

Removed the missing mock PDF from submission/detail links. Uploaded proposal PDFs up to 2 MB are stored as data URLs, with accurate metadata; larger accepted extraction files retain metadata only. PDF preview verifies a PDF signature and shows loading/unavailable states. The manual form and upload fallback preserve editable values. Missing project IDs now show an empty state instead of unrelated mock project data.

Added accessible keyboard selection in proposal review, visible focus, consistent status colors, responsive feedback, English/Thai status labels and page headings, storage failure feedback, and a render error boundary. Dashboard deadlines now derive from saved dates.

## Remaining limitations and assumptions

- Local browser persistence only: no backend, real authentication, email delivery, server backups, e-Office connection, digital signatures, or institutional submission.
- Unit completion -> e-Office, receipt -> staff review, review completion -> committee, and recorded certification plus endorsement -> active are explicit prototype assumptions. No online voting is implemented. Revision resubmission returns to staff review.
- Only core proposal fields are required for the demonstration: title, leader, objectives, methodology, valid ordered dates, and positive total budget with nonnegative components. This is not a claim of official RS-1 eligibility validation.
- PDF text extraction is heuristic and supports selectable text; no AI or OCR. PDFs up to 10 MB can be parsed, but only attachments up to 2 MB persist. Browser quota may be reached across multiple attachments and is reported.
- No real proposal/research/approval PDFs ship with the seed. Demo closure records deliberately show missing documents. A real attachment is required when demonstrating a new closure submission. The legacy PDF-generation utility remains unused because its Sarabun font assets are absent; no UI action claims generation works.
- Role selection and local storage do not provide production security, concurrency control, or cross-device synchronization. Reload intentionally returns to login. A page remount/refresh reads latest saved records.
- User-entered/free-text Thai content is preserved when switching to English; the app does not machine-translate research content. Canonical statuses and controls are translated.
